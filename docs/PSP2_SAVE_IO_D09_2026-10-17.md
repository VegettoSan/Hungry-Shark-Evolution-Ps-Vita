# D09: copia de archivos de guardado

Prueba privada solicitada por el propietario después de D08. P00 sigue ACTIVE, 0/13 aprobaciones. No se publica ni instala automáticamente.

## Evidencia

**VERIFIED, informe del propietario:** D08 muestra: `CloudSaveFacade.OnLoaded Got an exception while attempting to backup successfully loaded save file: System.IO.FileNotFoundException: sa` y entra al menú con progreso reiniciado. El texto recibido termina en `sa`; no identifica el archivo completo ni su ruta. La recuperación física del progreso de D08 no está confirmada.

**VERIFIED estático:** CloudSaveFacade.OnLoaded llama al consumidor de datos y después ejecuta File.Copy(savePath, savePath + .backup, true), con captura y registro de esa excepción. LocalLoad lo invoca desde el resultado Successful del cargador. Ese resultado puede corresponder a datos previos o recién creados; no demuestra que se hayan recuperado las monedas o el tiburón anteriores. El error de respaldo no se debe presentar como fallo demostrado del descifrado.

SaveData.Save escribe y cierra el archivo .sav.temp mediante FileStream, después usa File.Copy para actualizar .sav. Los caminos de respaldo y restauración de CloudSaveFacade también usan File.Copy. **INFERRED:** una incompatibilidad de esa operación en el backend podría afectar tanto al respaldo como a la escritura definitiva. No se afirma que File.Copy sea universalmente incompatible con PSP2: falta la comparación física. La documentación instalada del módulo describe cuota de guardado; no proporciona evidencia de ese fallo concreto. La cuota actual es 8192 KB y no se cambia sin una medida de uso real.

Se intentó lectura dirigida del guardado del título mediante el servidor que figuraba abierto en FileZilla; la conexión fue rechazada. No se obtuvo ni modificó ningún archivo de la consola. No hay copia física para verificar si existe un temporal válido o si conserva el progreso perdido.

## Cambio mínimo del experimento

Solo en UNITY_PSP2 sin UNITY_EDITOR, las cuatro copias afectadas pasan por HSEVitaSaveIO.Copy: escritura definitiva, respaldo tras carga, preservación .corrupted y restauración .backup. La lectura, formato, cifrado, claves, versión, contenido, ruta y checkpoints originales se conservan. No se cambia PlayerPrefs ni la corrección de identidad D08.

El adaptador abre primero el origen, copia mediante FileStream con buffers de 8 KiB, cierra el destino y compara longitud y bytes contra el origen. Rechaza mismo origen/destino. Conserva el contrato overwrite mediante Create/CreateNew. No utiliza File.Copy/Move/Delete para realizar la copia. Un error se propaga a los manejadores originales y conserva una descripción corta de la etapa y existencia de origen/destino para la franja. No se silencian errores para aparentar guardado correcto.

Antes de borrar el temporal anterior o reemplazar el archivo principal, se conserva el primer archivo existente con sufijo .d09-before; nunca se sobrescribe ese punto de recuperación. La sonda de la primera prueba conserva también local.sav, local.sav.temp y local.sav.backup existentes antes de la carga normal. Son datos privados del mismo contenedor. No se promociona un temporal a partida vigente sin validar su contenido y procedencia. El espacio extra requiere observación en la consola; no se conserva una copia nueva en cada frame o guardado.

**Límite:** la actualización del destino usa un stream ordinario; no se promete reemplazo atómico ni fsync. Si falla a mitad de una escritura, se informa el error y permanecen el temporal y el punto previo para investigar. Una comparación de bytes en el mismo proceso tampoco demuestra persistencia tras cierre o pérdida de alimentación.

## Pruebas

**VERIFIED, Unity 2018.2.19f1 en PC con target PSP2:** fixture aislada con el codec original, progreso 319 y después 320, marcador ficticio. Copia de respaldo y actualización de destino existente conservan los hashes exactos y el cargador original recupera progreso 320 y marcador. El primer .d09-before conserva su hash tras otro intento de preservación. Origen ausente y overwrite=false dejan el destino intacto; mismo archivo se rechaza sin dañarlo. File.Copy y streams pasan en PC. No se ejecuta Play Mode ni se tocan preferencias o partidas reales. Ocho comparaciones confirman las ramas previas de editor PSP2, Android, iOS y sin símbolos.

**UNTESTED en Vita:** la sonda temporal D09 compara File.Copy con streams usando exclusivamente archivos ficticios con nombres únicos bajo la ruta persistente del juego. Verifica los bytes de ambos destinos y limpia únicamente esos archivos de control. La franja distingue el resultado de esa comparación del IO real de la partida. No se usa el resultado de PC como prueba de compatibilidad Vita.

## Comprobación física

1. Conservar datos existentes al instalar D09. En el primer menú, fotografiar la franja completa, especialmente File.Copy, streams e IO. No borrar .sav, .temp, .backup ni .d09-before.
2. Terminar una partida por el flujo original y volver al menú. Observar WRITE event e IO verified, además de monedas, tiburón y mejoras. El evento por sí solo no acredita persistencia.
3. Cerrar el proceso y abrir el mismo VPK sin reinstalar. Comprobar LOAD y los valores del checkpoint anterior. Si hay error, la etapa IO diferencia abrir origen, abrir destino, copiar y verificar; conservar la franja.
4. Si el progreso anterior no reaparece, analizar por separado los archivos conservados. Una escritura correcta de D09 no recupera automáticamente datos ya sobrescritos antes de esta prueba.
