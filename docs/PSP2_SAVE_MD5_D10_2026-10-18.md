Los mismos datos ficticios pasan en en-US y fallan en es-ES, es-CO y fr-FR. La frontera de cultura invariable corrige la escritura y lectura de números decimales conservando el serializador y los valores; restaura la cultura del hilo mediante finally. Este defecto explica el rechazo JSON de las copias examinadas. **INFERRED:** es una causa del fallo físico comunicado. La procedencia exacta/contemporaneidad de esas copias respecto al renombrado manual y la cultura activa en esa sesión de Vita no se han verificado en este encargo.

**VERIFIED, informe del propietario:** ioPlus no resuelve la carga; el control D09 dice `File.Copy=FileNotFoundException sourceExists=True; streams=verified`, se observa `IO copy verified 20959 bytes` y `User save corrupted`. ## Cambios privados y diagnóstico

- `SaveData.cs`: solo PSP2 sin Editor usa `HSEVitaSaveJson` en las dos llamadas JSON; mantiene cifrado, PBKDF2, compresión, cabecera, versión, MD5 y progreso originales. Integra las verificaciones/etapas D10 y el wrapper de lectura exacta ya preparado antes de este encargo.
- `HSEVitaSaveJson.cs`: frontera cultural síncrona limitada al JSON de SaveData. No cambia la cultura permanente del juego ni convierte guardados antiguos.
- `HSEVitaSaveIO.cs`: conserva el algoritmo D09; añade traza de origen/destino y una copia previa `.d10-before` antes del primer reemplazo de principal/backup/corrupted. Temporal preservado antes de su reemplazo normal. No se promociona un temporal ni se borran datos de consola.
- `HSEVitaSaveDiagnostics.cs` / `HSEVitaD10Status.cs`: sonda temporal de etapas, rutas técnicas con IDs ocultos, tamaños, offsets, lecturas esperadas/reales, huellas cortas de archivo/payload/identidad y primer error con tipo y stack reducido. Máximo 120 registros por sesión, franja a 1 Hz; no solicita guardados ni ejecuta el control ficticio D09 al arrancar. Las copias D10 tienen un presupuesto total de 4 MiB y nunca reemplazan el primer punto de recuperación.

Después del cierre del temporal, el lector original de versión/cabecera y el mismo MD5 validan el contenedor; se reabre y repite. D09 compara cada byte del **guardado real** tras cerrar el destino; D10 valida/reabre el definitivo. Al arrancar, registra los contenedores persistidos y después la carga original registra `LOAD VALID` solo tras obtener el diccionario JSON. `SAVE TEMP VALID` y `COMMIT VALID` significan integridad del contenedor; no prueban el consumo del progreso ni durabilidad. Una foto del hash de COMMIT frente al siguiente LOAD permite comparar sesiones, considerando checkpoints posteriores legítimos.

**VERIFIED, fragilidad independiente:** una sola llamada Stream.Read no garantiza llenar el buffer. El parser original falla ante el mismo header válido si recibe un byte por Read; el wrapper preexistente `HSEVitaExactReadStream` lo llena mediante bucle y respeta EOF. Se integra solo al Load PSP2, conservando el parser. **UNTESTED:** que Vita haya producido lecturas cortas en el intento reportado; no se atribuye a ello el JSON decimal observado.
